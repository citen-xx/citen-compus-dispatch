TITLE|项目二：校园稀缺资源（智算中心 / 实训室）高可用调度中台
SUBTITLE|简历项目介绍 / 面试答辩材料 / GitHub 展示说明
NOTE|说明：以下内容用于简历与面试展示，重点突出微服务重构、高并发抢占、一致性控制与柔性事务闭环。
H1|1. 项目定位
P|这是一个面向校园场景的稀缺资源高可用调度中台，服务对象包括智算中心 GPU 节点、实训室机器工位、深度学习工作站和高价值实验资源时段名额。
P|项目本身不是问答系统，而是作为校园智能问答助手的底层业务执行引擎，无缝承接大模型 Function Calling 下发的预约、抢占、释放等资源调度指令。
P|项目目标是在突发流量和高并发抢占场景下，保证资源不超分配、预约状态一致、超时资源自动回收，以及核心调度链路的高可用。

P|Spring Boot。
P|Redis。
P|RabbitMQ。
P|Redisson。
P|Lua。
P|MyBatis-Plus。
P|MySQL。

H1|3. 核心定位与业务价值
P|当上层校园智能问答助手识别出“帮我预约今晚 8 点 GPU 节点”“帮我抢一个明天下午的实训室座位”这类意图后，会通过 Function Calling 将结构化业务指令下发给本项目。
P|本中台负责完成资源资格校验、额度抢占、预约落库、超时回收、异步通知和状态闭环，是连接大模型与真实业务系统的关键执行层。
P|从系统价值上看，它解决的是“业务指令落地执行”问题，而不是“自然语言理解”问题，因此非常适合作为简历中的工程化项目展示。
H1|4. 微服务架构设计
P|项目已从单体重构为 Maven 多模块微服务架构。
P|citen-gateway：统一流量入口、Token 鉴权、路由分发。
P|citen-user-service：用户凭证服务，负责验证码登录、用户信息、签到等能力。
P|citen-order-service：资源调度服务，负责资源管理、额度抢占、预约记录、超时违约处理、资源回补。
P|citen-user-api：跨服务调用 API 模块，定义 Feign 接口。
P|citen-common：公共实体、DTO、常量、工具类。
P|服务注册与发现基于 Nacos，网关路由基于 Spring Cloud Gateway。
P|这种拆分方式的优势是职责清晰、边界明确，方便后续扩容、限流、链路追踪和配置中心接入。
H1|5. 网关下沉与无状态化改造
P|项目通过 Spring Cloud Gateway 构建统一流量入口，将原本服务内的会话拦截逻辑前移到网关。
P|网关负责解析 Token、识别白名单接口、校验用户登录态、刷新登录态有效期，并将用户身份信息透传给下游微服务。
P|这样做的好处是将认证从具体业务服务中剥离，推动用户服务和资源调度服务逐步走向无状态化设计。
P|服务发现与动态配置依托 Nacos，使整个调度系统更适合在校园场景下做多实例部署与高可用扩展。
H1|6. 并发防线与防雪崩机制
P|校园中的实训室开放时段、智算资源开放窗口通常会在固定时间形成突发式脉冲流量，这是典型的高并发抢占场景。
P|项目设计上引入 Sentinel，用于对核心预约 API 做 QPS 限流、滑动窗口保护和非关键链路降级。
P|核心目标不是单纯“限制流量”，而是在流量冲击下保护资源调度主链路，避免大量并发请求挤爆数据库、缓存或消息系统，进而引发级联雪崩。
P|这部分非常适合在简历和面试中突出“高可用设计能力”。
H1|7. 资源抢占强一致性控制
P|项目最核心的技术点是高并发抢占下的强一致性控制。
P|传统数据库互斥锁在高并发下吞吐低、竞争重、扩展性差，因此项目底层使用 Redis + Lua 脚本原子完成资格校验与额度扣减。
P|Lua 脚本在 Redis 内部原子完成三件事：判断资源额度是否充足、判断用户是否已重复预约、扣减额度并记录抢占资格。
P|Lua 校验通过后，将预约消息写入 Redis Stream，主线程快速返回，避免同步阻塞数据库。
P|异步消费端再使用 Redisson 分布式锁按用户维度做串行化处理，防止同一用户在极端并发下重复落库。
P|最终在数据库层再使用条件更新做一致性兜底，从缓存层、分布式锁层、数据库层形成完整的并发防线。
H1|8. 柔性事务闭环与违约资源回补
P|针对“预约成功但未按时签到”或“算力任务未在规定时间内激活”导致的资源闲置问题，项目引入 RabbitMQ 延迟队列和死信队列，构建柔性事务闭环。
P|预约创建成功后发送延迟消息，若在规定时间内未完成确认，则消息进入死信队列，由超时监听器消费。
P|监听器执行两步核心补偿：一是将 Reservation 状态标记为超时违约；二是将 ResourceQuota 的可用额度加 1。
P|这种设计避免了传统定时任务轮询扫表的高 I O 开销，也让资源释放更加实时和可控。
P|从工程角度看，这体现的是事件驱动架构、柔性事务和最终一致性设计能力。
H1|9. 深分页与大数据量查询优化
P|项目在管理端存在大量历史调度日志与预约记录查询需求，压测后形成了百万级数据量。
P|针对深分页慢查询问题，项目使用 EXPLAIN 执行计划分析 SQL，结合覆盖索引与延迟关联分页方案进行重构。
P|优化后，深分页慢查询耗时从 3.2 秒降低到 150 毫秒以内。
P|这部分体现了数据库执行计划分析、索引理解和后台大数据量查询优化能力，是面试中很加分的一块。
H1|10. 对外核心接口
P|POST /reservation/reserve/{id}：高并发抢占资源额度。
P|GET /reservation/admin/page：分页查询预约记录。
P|GET /lab/{id}：查询实训室或算力中心详情。
P|GET /lab/of/type：按资源类型查询可用中心。
P|GET /resource/list/{labId}：查询某中心下的资源列表。
P|POST /resource：新增资源。
P|POST /resource/quota：新增资源额度。
